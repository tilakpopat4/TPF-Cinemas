# Plan 07-02: Pending Updates Tab — Post-Publish Edit Approval Workflow

**Phase:** 7 — Staff Curation Console & Moderation Queue
**Plan:** 2 of 2
**Status:** Pending
**Requirements:** STUDIO-05, STAFF-05
**Created:** 2026-10-05

---

## Goal

Build the complete post-publish edit workflow:
1. **Creator side (Studio app):** "Edit Published Film" button on Live films in the creator dashboard — opens the existing FilmEditorModal pre-populated with live data; on submit calls `propose_film_update()` instead of `submit_film()`. Dashboard shows "Pending Update" badge while awaiting review.
2. **Staff side (Staff Console):** New "Pending Updates" sub-tab (or inline section) in the Review Queue showing a field-by-field **diff view** of proposed vs. live values. Curator can approve (`apply_film_update()`) or reject (`reject_film_update()` — mandatory notes).

## Context

Plan 07-01 laid the DB foundation (migration, 3 RPCs, types). This plan builds the UI on top.

**Key existing pieces to reuse:**
- `ReviewModal.tsx` — modal shell and pattern to reuse for the update diff panel
- `DecisionBox.tsx` — decision + notes pattern to adapt for approve/reject update
- `apps/studio/src/components/editor/FilmEditorModal.tsx` — existing multi-step wizard
- `apps/studio/src/App.tsx` — creator dashboard entry point; Edit button goes here

## Tasks

### T-07-02-01 · Studio — "Propose Edit" action on published films
**Type:** tracer
**App:** `apps/studio`

In the creator dashboard (wherever published/Live films are shown — likely a status tab or film card), add an "Edit Details" button for `status === 'published'` films.

**Behavior:**
- Button label: "Edit Published Film" (pencil icon)
- Clicking opens a modal/form pre-populated with the current film's live values
- Fields available to edit: title, synopsis, director_note, runtime_minutes, language, release_year, age_rating, poster_url, video_ref (same as the submission wizard fields — NOT status/is_featured/slug)
- **Cannot edit while an update is pending** — if film has `status === 'update_pending'`, show a "Pending Staff Review" badge instead of the Edit button, with a tooltip explaining the live film is unchanged
- On "Submit Changes": call `propose_film_update(filmId, changedFields)` RPC — only include fields that actually changed (diff vs. original values before edit)
- On success: show confirmation toast, creator dashboard updates badge to "Pending Update"

**Implementation notes:**
- Create `apps/studio/src/components/editor/ProposeUpdateModal.tsx` — a simplified single-page form (not multi-step wizard) showing all editable fields, with change tracking (dirty state per field)
- Create `apps/studio/src/hooks/useProposeUpdate.ts` — wraps the `propose_film_update` RPC call
- The modal only submits `proposed_changes` as a diff object: `{ synopsis: "new text" }` — not the full film record
- Add `'update_pending'` to the Studio's `FilmStatus` type (mirror the staff app type update)

**Verify:**
- Published film card shows "Edit Published Film" button
- Editing only synopsis → `proposed_changes = { synopsis: "..." }` (not all fields)
- `update_pending` film shows "Pending Staff Review" badge, no Edit button
- Successful proposal → `film_updates` row inserted with `status = 'pending'`, film status = `update_pending`

### T-07-02-02 · Staff — `usePendingUpdates` hook
**Type:** task
**App:** `apps/staff`
**File:** `apps/staff/src/hooks/usePendingUpdates.ts`

New hook that fetches all `film_updates` with `status = 'pending'`, joining film title/poster and filmmaker name.

```typescript
// Query shape:
supabase
  .from('film_updates')
  .select(`
    *,
    film:films!film_updates_film_id_fkey (
      id, title, slug, poster_url, status, language, runtime_minutes
    ),
    filmmaker:profiles!film_updates_filmmaker_id_fkey (
      id, display_name, avatar_url
    )
  `)
  .eq('status', 'pending')
  .order('created_at', { ascending: false })
```

Include realtime subscription on `film_updates` table (same pattern as `useReviewQueue`).

Returns: `{ updates: FilmUpdate[], loading, error, refresh }`.

**Verify:** Hook returns pending updates; realtime fires when a new `film_updates` row is inserted.

### T-07-02-03 · Staff — `PendingUpdatesDiffPanel` component
**Type:** task
**App:** `apps/staff`
**File:** `apps/staff/src/components/queue/PendingUpdatesDiffPanel.tsx`

Full-panel component that shows a **side-by-side diff** of proposed changes vs. current live values.

**Layout:**
```
┌─────────────────────────────────────────────────────────┐
│  🎬 Film Title  ·  Requested by Creator Name  ·  2h ago  │
├──────────────────────────┬──────────────────────────────┤
│  CURRENT LIVE            │  PROPOSED CHANGE             │
├──────────────────────────┼──────────────────────────────┤
│  synopsis: "Old text..." │  synopsis: "New text..."     │
│  (unchanged fields hidden)                              │
├──────────────────────────┴──────────────────────────────┤
│  [✓ Approve Changes]         [✗ Reject with Notes]      │
└─────────────────────────────────────────────────────────┘
```

**Implementation:**
- Receive props: `update: FilmUpdate`, `liveFIlm: Film`, `onComplete: () => void`
- Iterate over `update.proposed_changes` keys only — show only changed fields
- Each row: field label | live value (muted, red tint if different) | proposed value (green tint)
- Special handling: poster_url → show both images as thumbnails side-by-side
- **Approve action:** calls `apply_film_update(update.id, optionalNotes)` — optional curator note
- **Reject action:** requires notes (min 10 chars) → calls `reject_film_update(update.id, notes)`
- Match the visual language of `DecisionBox.tsx` (dark cards, amber accents, motion animations)
- Loading/error states on both buttons

**Verify:**
- Panel shows only changed fields (not all film fields)
- Poster thumbnails display when poster_url changes
- Approve → `apply_film_update` fires → film status returns to `published`, update marked `approved`
- Reject → requires notes → `reject_film_update` fires → film status returns to `published`, update marked `rejected`
- Audit log entries written for both actions

### T-07-02-04 · Staff — Integrate Pending Updates into the Queue view
**Type:** task
**App:** `apps/staff`

Integrate the pending updates panel into the existing staff console flow.

**Option A (recommended):** When a film with `status === 'update_pending'` is clicked in QueueTable, `ReviewModal` detects the status and renders a "Proposed Changes" tab alongside the existing "Film Details" / "Credits" / "Licence" tabs. The `PendingUpdatesDiffPanel` is rendered in that tab.

**Option B (fallback):** A separate `PendingUpdatesModal` opened when clicking an `update_pending` row.

Use Option A — it reuses the existing modal shell and keeps context (the staff member can see the current live film content AND the proposed changes in the same modal).

**Changes to `ReviewModal.tsx`:**
- When `film.status === 'update_pending'`: add a "📋 Proposed Changes" tab button in the modal tab bar, highlighted with amber accent
- Fetch the pending update for this film: `film_updates` where `film_id = film.id AND status = 'pending'` (single query on modal open)
- Render `PendingUpdatesDiffPanel` when the "Proposed Changes" tab is active
- On `PendingUpdatesDiffPanel.onComplete`: call `ReviewModal`'s `onActionComplete`

**Changes to `App.tsx`:**
- Pass a `usePendingUpdates` hook result to show pending update count badge in `StaffHeader`

**Verify:**
- Clicking an `update_pending` film in QueueTable opens ReviewModal with "Proposed Changes" tab
- Tab shows `PendingUpdatesDiffPanel` with correct diff
- After approve/reject, modal closes, queue refreshes, film no longer shows `update_pending`
